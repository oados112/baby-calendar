# תוכנית בנייה — אתר מעקב תינוק (בסגנון Baby Daybook)

מסמך תכנון מלא. **אתר** פרטי שנכנסים אליו מכל דפדפן — אנדרואיד, אייפון, מחשב. אנחנו שנינו מנהלים, ואפשר לצרף בני משפחה כרושמים או כצופים.

> **שני עקרונות שגוברים על הכל:** (1) **עלות אפס מוחלטת** — לא נשתמש בשום שירות שדורש כרטיס אשראי או עלול לחייב. (2) **UI/UX ברמה גבוהה** — זה כלי שמשתמשים בו עשרים פעם ביום, חלקן בשלוש לפנות בוקר עם תינוק ביד אחת.

## 1. מטרות ואילוצים

| נושא | החלטה |
|---|---|
| סוג המוצר | אתר רגיל בכתובת URL. אין חנות אפליקציות, אין התקנה, אין הורדה |
| גישה | פותחים קישור בדפדפן ומתחברים. עובד מכל מכשיר, כולל מכשיר חדש/מושאל |
| "הוספה למסך הבית" | **אופציונלי בלבד** — נותן אייקון ומסך מלא, ובאייפון גם מאפשר התראות פוש. האתר עובד מלא גם בלי זה |
| משתמשים | רשימה לבנה קשיחה, אין הרשמה פתוחה. שלוש רמות: **מנהל** (אנחנו) / **רושם** / **צופה** |
| שפה | עברית, RTL מלא, תאריכים ושעות בפורמט ישראלי |
| טכנולוגיה | Next.js 15 + TypeScript + Tailwind + Supabase (Postgres + Auth + Realtime) + Vercel |
| התראות | Web Push — תזכורות זמן, סנכרון בין ההורים, טיימר פעיל ברקע |
| עלות | **0 ₪, ללא כרטיס אשראי בכלל.** ראו סעיף 1.1 |
| ניהול | הכל ב-Git (repo פרטי ב-GitHub), פריסה אוטומטית בכל push ל-`main` |

### אילוצים שחשוב לדעת מראש
- **התראות באייפון**: Safari שולח התראות פוש רק אחרי "הוסף למסך הבית", ורק ב-iOS 16.4 ומעלה. אין דרך לעקוף — אבל זו לחיצה אחת חד-פעמית. באנדרואיד ובמחשב זה עובד ישירות מהדפדפן.
- **טיימר ברקע**: דפדפן לא מריץ טיימר כשהוא סגור. הפתרון: הטיימר נשמר בשרת עם זמן התחלה ומחושב מחדש בכל פתיחה, וההתראה עליו נשלחת מהשרת.
- **Supabase בחינם** נרדם אחרי 7 ימי חוסר פעילות. ה-cron שלנו מחזיק אותו ער ממילא.

## 1.1 עלות אפס — איך מבטיחים את זה בפועל

**הכלל:** לא מפעילים שום שירות שדורש כרטיס אשראי, ולא מפעילים שום שדרוג בתשלום — גם לא "חינם ל-30 יום".

| שירות | תוכנית | דורש כרטיס? | מה מקבלים בחינם | האם מספיק לנו |
|---|---|---|---|---|
| **GitHub** | Free | לא | repo פרטי + collaborators ללא הגבלה | בשפע |
| **Vercel** | Hobby | **לא** | 100GB תעבורה/חודש, פריסות ללא הגבלה, HTTPS ודומיין `.vercel.app` | בשפע (2–5 משתמשים) |
| **Supabase** | Free | **לא** | 500MB DB, 1GB אחסון, 50K משתמשים, Realtime, pg_cron | בשפע |

### הפרש חשוב מהתוכנית המקורית: ה-cron עובר ל-Supabase
ב-Vercel Hobby (החינמית) משימות cron מוגבלות ל**הרצה אחת ביום**. זה לא מספיק למנוע תזכורות שצריך לבדוק כל כמה דקות.

**הפתרון (חינמי לגמרי):** `pg_cron` + `pg_net` בתוך Supabase עצמו. Postgres מריץ אצלנו בדיקה כל 5 דקות וקורא ל-Edge Function ששולחת את ההתראות. אין הגבלת תדירות ואין עלות. בונוס: זה גם מה שמונע מהפרויקט להירדם.

### מנגנוני הגנה מעלות מפתיעה
1. **לא נחבר אמצעי תשלום** לאף חשבון. בלי כרטיס, החשבון לא *יכול* לחייב — במקרה חריגה השירות פשוט נעצר עד תחילת החודש.
2. **ב-Vercel**: לא מפעילים Analytics/Speed Insights/Blob/KV/Image Optimization בתשלום. תמונות עולות ל-Supabase Storage, לא ל-Vercel.
3. **התאמת תמונות בצד הלקוח** לפני העלאה (דחיסה ל-WebP) כדי לא להתקרב לתקרת האחסון.
4. **בדיקה חודשית** של מסכי השימוש בשני השירותים.
5. **תוכנית מילוט**: אם Vercel אי פעם ידרוש תשלום, המעבר ל-Cloudflare Pages (גם היא חינמית וללא כרטיס) הוא עניין של שעה — לכן לא נשתמש באף פיצ'ר ייחודי ל-Vercel. זה שיקול שמנחה את הקוד מהיום הראשון.

## 1.3 עקרונות UI/UX

האתר נועד לשימוש עייף, במצוקה, ביד אחת. מכאן נגזרות ההחלטות:

1. **שלוש שניות לרישום** — מהמסך הראשי ועד "נרשם" בלחיצה אחת או שתיים. רישום מהיר עם ברירות מחדל חכמות (הצד הבא בהנקה, הכמות האחרונה בבקבוק) וכפתור "פרטים" למי שרוצה לדייק.
2. **אזור אגודל** — כל הפעולות התכופות בשליש התחתון של המסך. הכפתורים גדולים (מינימום 56px) ומרווחים.
3. **מבט חטוף** — המסך הראשי עונה על "מתי אכל לאחרונה?" בלי לקרוא: מספר גדול, צבע לפי סף, טבעת התקדמות.
4. **מצב לילה אמיתי** — לא רק "כהה", אלא מסך שחור-אמיתי בגוונים חמים ובבהירות נמוכה, נכנס אוטומטית לפי שעה, כדי לא לסנוור בשלוש לפנות בוקר ולא להעיר את התינוק.
5. **מיידיות** — כל פעולה מופיעה מיד (optimistic UI) עם ביטול קל, בלי ספינרים וללא מסכי אישור מיותרים.
6. **טעות לא עולה ביוקר** — "בטל" צף אחרי כל רישום, מחיקה רכה, והיסטוריית עריכות.
7. **שפה אנושית** — "לפני שעה ורבע", לא "13:42". אין ז'רגון.
8. **תנועה מדודה** — אנימציות קצרות (150–200ms) שמסבירות מה קרה, וכיבוד `prefers-reduced-motion`.
9. **נגישות** — ניגודיות AA לפחות, תמיכה בהגדלת גופן מערכתית, ניווט מקלדת מלא, תוויות ARIA בעברית.
10. **RTL אמיתי** — לא תרגום של פריסה שמאלית. אייקונים, חצים, גרפים וכיווני החלקה מותאמים.
11. **עקביות** — מערכת עיצוב אחת: צבע לכל סוג אירוע, מרווחים בסולם קבוע, רדיוסים אחידים, ספריית רכיבים משותפת.
12. **אפס מצבים ריקים מביכים** — כל מסך ריק מסביר מה לעשות ומציע פעולה.

## 2. פיצ'רים — פירוק מלא (מקבילה ל-Baby Daybook)

### 2.1 ליבה — רישום אירועים

**האכלה**
- הנקה: טיימר שד שמאל / ימין, החלפת צד באמצע, סיכום זמן לכל צד, זיכרון "איזה צד אחרון"
- בקבוק: כמות במ"ל, סוג (חלב אם / תמ"ל / שאוב)
- שאיבה: צד, כמות, משך
- מוצקים: תיאור מזון, כמות, תיוג "מזון חדש" למעקב אלרגיות
- מים ושתייה

**חיתולים**
- סוג: פיפי / קקי / שניהם / יבש
- צבע ומרקם (רשימה קבועה עם צבעים ויזואליים)
- דגל פריחה/אדמומיות

**שינה**
- טיימר התחלה/סיום, או הזנה ידנית של טווח שעות
- מיקום (מיטה / עגלה / ידיים), איכות
- חישוב אוטומטי: סה"כ שינה ביום, שינת לילה מול יום

**בריאות**
- חום (°C) + מיקום מדידה
- תרופות: שם, מינון, שעה — כולל מרווח מינימלי בין מנות והתראה עליו
- ויטמין D ותוספים עם תזכורת יומית
- חיסונים: לוח החיסונים הישראלי לפי גיל (טיפת חלב), תאריך מתן ותזכורת מראש
- ביקורי רופא / טיפת חלב עם הערות

**גדילה**
- משקל, אורך, היקף ראש
- גרף לאורך זמן **על גבי עקומות האחוזונים של WHO**

**פעילות ואחר**
- זמן בטן, אמבטיה, טיול, משחק
- אבני דרך (חיוך ראשון, התהפכות, שן ראשונה) עם תמונה
- הערה חופשית עם תמונה

### 2.2 מסכים
1. **מסך בית** — הלב של האתר:
   - כרטיסי "מה עכשיו": כמה זמן עבר מההאכלה / החיתול / השינה האחרונים, בצבע לפי סף (ירוק/כתום/אדום)
   - כפתורים גדולים לרישום מהיר בלחיצה אחת
   - טיימרים פעילים בראש המסך
   - ציר זמן של היום
2. **יומן** — כל האירועים לפי יום, גלילה אחורה, סינון לפי סוג, עריכה ומחיקה
3. **סטטיסטיקות** — גרפים יומי/שבועי/חודשי: מספר האכלות, סה"כ מ"ל, שעות שינה, מספר חיתולים, heatmap של דפוסי שינה ב-24 שעות
4. **גדילה** — מדידות וגרפי אחוזונים
5. **הגדרות** — פרופיל תינוק, ספי התראה, ניהול תזכורות, הזמנת בן/בת זוג

### 2.3 מה שייחודי לנו
- **סנכרון חי**: אשתי רושמת האכלה — זה מופיע אצלי תוך שנייה בלי רענון
- **מי רשם**: כל אירוע מתויג בשם ההורה שרשם אותו
- **עובד גם בלי אינטרנט**: רישום נשמר מקומית ומסתנכרן כשהחיבור חוזר
- **תמיכה בכמה ילדים** — מוכן בסכמה מהיום הראשון
- **ייצוא** ל-CSV/PDF לרופא
- **תקציר יומי** בהתראה: "אתמול: 8 האכלות, 14 שעות שינה, 6 חיתולים"

## 4. מודל נתונים (Postgres)

```sql
-- משפחה = יחידת ההרשאה
families            (id, name, created_at)
family_members      (family_id, user_id, display_name, role, joined_at, is_suspended)
                    -- role enum: admin | logger | viewer
invites             (id, family_id, email, role, token_hash, expires_at,
                     created_by, accepted_at, revoked_at)
babies              (id, family_id, name, birth_date, sex, photo_url, is_active)

-- טבלת אירועים אחת גמישה, במקום 12 טבלאות כמעט זהות
events (
  id            uuid pk,
  baby_id       uuid fk,
  family_id     uuid fk,          -- משוכפל לצורך RLS מהיר
  type          event_type,       -- enum: feed_breast | feed_bottle | pump | solids |
                                  --       diaper | sleep | temperature | medicine |
                                  --       growth | activity | milestone | note
  started_at    timestamptz not null,
  ended_at      timestamptz,      -- לאירועים עם משך (שינה, הנקה)
  data          jsonb not null,   -- השדות הייחודיים לכל סוג
  note          text,
  photo_url     text,
  created_by    uuid fk,          -- מי רשם
  created_at    timestamptz,
  updated_at    timestamptz,
  deleted_at    timestamptz       -- מחיקה רכה, לא אובדן נתונים
)

-- טיימר שרץ כרגע, משותף בין שני המכשירים
active_timers       (id, baby_id, family_id, type, side, started_at, started_by)

-- התראות
push_subscriptions  (id, user_id, endpoint, p256dh, auth, user_agent, created_at)
reminder_rules      (id, family_id, baby_id, kind, config jsonb, is_enabled)
                    -- kind: feed_gap | sleep_gap | diaper_gap | medicine | vitamin |
                    --       timer_running | daily_summary | partner_activity
notifications_log   (id, user_id, rule_id, sent_at, payload)   -- מניעת כפילויות וספאם
```

**אינדקסים:** `events(baby_id, started_at desc)`, `events(family_id, type, started_at desc)`, GIN על `data`.

**דוגמאות לשדה `data`:**
```jsonc
// feed_breast
{ "left_sec": 420, "right_sec": 300, "last_side": "right" }
// feed_bottle
{ "amount_ml": 120, "kind": "formula" }
// diaper
{ "pee": true, "poo": true, "color": "yellow", "texture": "seedy", "rash": false }
// growth
{ "weight_g": 4300, "height_cm": 55.5, "head_cm": 38.2 }
```

**RLS על כל טבלה — קריאה לפי חברות, כתיבה לפי תפקיד:**
```sql
-- קריאה: כל חבר משפחה פעיל (כולל צופה)
create policy "read: any active member" on events
  for select using (is_active_member(family_id));

-- הוספה: מנהל או רושם בלבד
create policy "insert: admin or logger" on events
  for insert with check (has_role(family_id, array['admin','logger']));

-- עריכה/מחיקה: מנהל תמיד; רושם רק את מה שהוא עצמו רשם, ועד 24 שעות
create policy "update: admin, or own recent row" on events
  for update using (
    has_role(family_id, array['admin'])
    or (created_by = auth.uid() and created_at > now() - interval '24 hours')
  );
```

## 5. מערכת ההתראות

### 5.1 תשתית
- מפתחות VAPID נוצרים פעם אחת ונשמרים כמשתני סביבה
- ה-Service Worker רושם מנוי התראות לכל מכשיר בטבלת `push_subscriptions`
- השליחה מהשרת בספריית `web-push`

### 5.2 סוגי ההתראות
| התראה | מתי | הערות |
|---|---|---|
| **פער האכלה** | עברו X שעות מההאכלה האחרונה | X נקבע בהגדרות (ברירת מחדל 3 שעות), ניתן לכבות בלילה |
| **פער שינה** | התינוק ער יותר מ-X | עוזר למנוע עייפות יתר |
| **תרופה / ויטמין** | שעה קבועה או X שעות מהמנה הקודמת | כולל חסימת מנה מוקדמת מדי |
| **חיסון קרוב** | 3 ימים לפני המועד לפי לוח טיפת חלב | |
| **טיימר רץ** | טיימר פעיל מעל X דקות | "שכחת לעצור טיימר שינה?" עם כפתור עצירה בהתראה |
| **פעילות בן/בת הזוג** | אירוע נרשם ע"י ההורה השני | נשלח רק לשני, ניתן להשתקה |
| **תקציר יומי** | שעה קבועה, למשל 21:00 | |

### 5.3 המנגנון
- **pg_cron בתוך Supabase** רץ כל 5 דקות וקורא ל-Edge Function `reminders` (חינמי, ללא הגבלת תדירות)
- שולף לכל תינוק את זמן האירוע האחרון מכל סוג, ומשווה לכללים ב-`reminder_rules`
- בודק מול `notifications_log` שלא נשלחה התראה זהה לאחרונה
- שולח לכל המכשירים הרשומים של המשתמשים הרלוונטיים
- **שעות שקט**: טווח שבו לא נשלחות התראות, למעט קריטיות
- **כפתורים בתוך ההתראה**: "רשמתי האכלה" / "עצור טיימר" / "נודניק 15 דקות"

## 8. ניהול ב-Git

**ענפים** (פשוט, מתאים לשניים):
- `main` — מה שרץ בפרודקשן. כל מיזוג = פריסה אוטומטית
- `feat/<שם>` — ענף לכל פיצ'ר, נכנס דרך PR

**כללים:**
- הגנה על `main`: חובה PR ובדיקת build ירוקה
- הודעות commit בפורמט `feat:` / `fix:` / `chore:`
- כל PR מקבל **כתובת תצוגה מקדימה** מ-Vercel — אפשר לבדוק פיצ'ר לפני שהוא נכנס
- מיגרציות בסיס הנתונים נשמרות כקובצי SQL ב-`supabase/migrations/` — גם ה-DB תחת ניהול גרסאות

**מבנה תיקיות:**
```
app/            מסכים
  (auth)/       התחברות
  (app)/        האזור המוגן
  api/          נקודות קצה (התראות, cron)
components/     רכיבי ממשק
lib/            חיבורי supabase, שאילתות, תאריכים, התראות
supabase/
  migrations/   מיגרציות SQL
types/          טיפוסים מגונרטים
public/         manifest, אייקונים, service worker
```
